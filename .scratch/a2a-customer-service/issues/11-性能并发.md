- 目标负载规模与是否压测。
- 检索 CPU 推理（延迟 + 内存大头）在并发下如何防 OOM、限并发。
- 接待（有状态、编排）如何处置多会话并发。
- LLM 调用的限流 / 重试 / 超时。
- 延迟软目标（检索 / 端到端 / 对外首 token）。
- 模型冷启动预热。
- Milvus / Redis 并发处理。
- 资源兜底（与 08 的模型外置切换衔接）。

## Answer

性能 / 并发定稿。**定位：作品集是「单人演示 + 低并发（≤ ~5 并发会话）」，不承诺生产级并发、不专门压测；只做一次手动冒烟记录真实数字。** 一切并发度 / 超时 / 预热做成 `config/` 参数，不硬编码。

### 1. 负载定位与压测
- 目标：**演示级低并发**（同时 ~5 会话以内）。
- **不做正式压测**；仅跑一次**手动冒烟**：单流（1 并发）+ 3 并发，各测「检索耗时 / 端到端耗时 / 首 token」，数字写进 `README.md` 作展示与回归对照，不设硬门禁（与 10「不配 CI」一致）。

### 2. 检索 CPU 推理（延迟 + 内存大头）
- 检索 Agent **单进程、模型进程内只加载一份**（对齐 04）。
- 并发防护：用**进程内信号量 / 单 worker 串行化 embedding+rerank**，把「同时推理数」限成配置项（**默认 1**），超出排队而非并发——这是 6G VM 防 OOM 的主闸门。
- 推理并发数与「是否切外置」都可配；压不上去时降并发或走 §7 外置兜底。

### 3. 接待（有状态 / 编排）并发
- 接待 **uvicorn 单 worker + asyncio**（作品集足够）；会话按 `context_id` 天然隔离（Redis，06 §9）。
- 不做多副本；将来需横向扩才引入多副本 + Redis 共享（本作品集范围外）。

### 4. LLM 调用（DashScope）
- **不自建限流中间件**；靠接待对下游**非流式串行**天然压并发（06 §5）。
- 超时沿用 `client.timeout_seconds: 120`（05 教训，防冷启动超时）。
- 对 LLM 调用加 **1–2 次指数退避重试**兜限流(429)/瞬时错误；仍失败→走 06 §7 兜底话术、任务 `COMPLETED`。
- 可选全局并发上限信号量（配置项，默认不限）。

### 5. 延迟软目标（SLO-like，仅展示/冒烟对照，非硬 SLA）
- 检索（含 rerank）单查询 **P95 ≤ ~2s**；
- 端到端完整答复 **≤ ~15s**（含 LLM；冷启动极端容忍到 120s 超时）；
- 对外 SSE **首 token (TTFB) ≤ ~8s**。
- 数字随 §1 冒烟写进 `README.md`。

### 6. 冷启动预热
- 检索 Agent **启动即 warm-up**（加载 BGE-M3 + reranker 并跑一次哑查询），避免首请求撞模型冷启动超时；答复/接待首次 LLM 调用由 §4 超时+重试兜。
- query / embedding **不做缓存**（作品集，收益低风险高）。

### 7. 中间件与资源兜底
- Milvus / Redis 非瓶颈，不做专门并发处理；Redis 用连接池即可。
- OOM 兜底**沿用 08**：模型来源做成配置项，VM 扛不住时改配置切「模型外置到开发机 / 远端推理服务」，不改代码；本票只新增「检索并发推理数」这一配置项。

### 8. 配置项（全部落 `config/`）
- `retrieval.infer_concurrency`（默认 1）；`reception.uvicorn_workers`（默认 1）；`llm.timeout_seconds`（默认 120）；`llm.max_retries`（默认 1–2）；`warmup.enabled`（默认 true）；冒烟延迟目标仅作 README 文案、不进运行时。

### 依赖（后续实施票使用）
- 检索 Agent 内加 `asyncio.Semaphore(infer_concurrency)` 包 embedding+rerank。
- 三服务各自 uvicorn 启动参数走配置；接待/答复 `workers=1`。
- LLM 客户端封装退避重试；`warmup` 启动钩子（检索）。
- 一份 `docs/records/` 冒烟记录模板（单流 / 3 并发 的检索·端到端·TTFB 数字），结果引用进 `README.md`。
