## Question

提示词记录规范的细节怎么定？

承接地图「用户既有要求」：**不断记载关键的、有用的提示词，这些提示词需能最终复现从当前到最后上线的全部效果。**

待定：
- 记录载体与位置？
- 记录的粒度与版本策略（「可复现」到什么程度）？
- 单条记录包含哪些字段？
- 哪些提示词纳入记录范围？
- 生成方式（手工 / 从配置生成 / 加校验）？
- 更新时机与流程？

## Answer

提示词记录规范定稿。目的：**「不断记载关键的、有用的提示词，能最终复现从当前到上线的全部效果」**。

### 1. 载体与位置
- 仓库内 `docs/prompts/` 目录，按 Agent 分文件：
  - `docs/prompts/reception.md`（接待：分流判定提示词、兜底话术模板）
  - `docs/prompts/retrieval.md`（检索：如涉及 LLM 提示词）
  - `docs/prompts/reply.md`（答复：生成提示词 + system prompt）
  - `docs/prompts/README.md`（顶层索引 / 变更日志：列出全部提示词 ID 与当前版本）

### 2. 粒度与可复现口径
- 每个提示词维护「当前版 + 变更历史」。
- 每次改动记一条：版本号、日期、改动原因、关联 ticket / commit、**当时的模型与参数快照**（model / temperature / max_tokens）。
- 可复现 = 任一历史版本的提示词原文 + 当时的模型 / 参数。

### 3. 单条记录字段
- 提示词 ID
- 所属 Agent
- 用途
- 提示词原文（中文）
- 输入变量（占位符及其来源）
- 输出格式（结构化 schema，对齐 06 契约，如 `{is_service, intent, reason}`）
- 生效模型与参数（model / temperature / max_tokens）
- 生效检索/排序参数（`top_k`、rerank 阈值、Milvus 检索参数等影响效果的运行时参数）
- 版本与日期
- 关联 ticket / commit
- 实测效果备注

### 4. 范围
- 三个 Agent 的全部 LLM 提示词：接待的分流判定提示词、答复的生成提示词（含 system prompt）、兜底话术模板。

### 5. 生成与校验
- 记录文档**手工维护**（承载「为什么改 / 效果如何」这类机器生成不出来的上下文）。
- 加一条**一致性校验**：小脚本 / 测试比对「记录中的提示词原文 + 生效参数」与「`config/agents/*.yaml` / `config/common.yaml` 的对应值」（含 `top_k`、rerank 阈值等运行时参数），不一致即报错。
- YAML 是运行时唯一源；记录是档案；校验专门防漂移。

### 6. 更新时机与流程
- 「改提示词**或生效参数**（`top_k`、rerank 阈值等）= 同一次提交里同步更新记录」纳入完成定义（DoD）；配置变更与记录变更进**同一 commit**。

### 7. 效果证据
- 每个版本附**一条代表性样例 + 关键指标**（如分流判定的一组样例及对错、一条代表性问答）；`top_k` / rerank 阈值等**参数变更同样附「改动前后对照样例 + 指标」**。
- 不追求穷举，避免变成负担；目的是让「新旧版本对比」和「面试讲解」有实证。

### 8. 语言
- 提示词一律**中文**（目标模型为国产系，业务语料为中文）。

### 9. 影响效果的运行时参数也纳入记录
- 影响输出效果但**非提示词**的参数（`top_k`、rerank 阈值、Milvus 检索参数等）**一并纳入本规范**：在 `docs/prompts/` 对应 Agent 文件里，与提示词同条目记录「当前值 + 变更历史 + 生效日期 + 关联 `config/` 路径与 commit」。
- 一致性校验同样覆盖这些参数：比对「记录里的参数值」与「`config/agents/*.yaml` / `config/common.yaml` 的实际值」，不一致即报错（与提示词原文共用同一条校验，防漂移）。
- 运行时唯一源仍是 `config/`；`docs/prompts/` 是档案。
- 边界修订说明：本条由第 1 轮原「非提示词参数不进本规范」的自划边界，在接力会话经用户确认改为「纳入记录」。

### 依赖（后续实施票使用）
- 新建 `docs/prompts/`（各 Agent 当前版文件 `reception.md` / `retrieval.md` / `reply.md` + 顶层 `README.md` 索引）与 `docs/records/`（同名变更历史文件）。
- 新增一致性校验脚本 / 测试（比对 `docs/prompts/` 记录的提示词原文与生效参数 vs `config/agents/*.yaml` / `config/common.yaml`）。
- 提示词本身在实施票中编写，按本规范登记。
