## Answer

测试策略定稿。原则：**作品集务实分层——单测保「逻辑/契约/编排」确定性与低成本，检索 golden set 保「效果有实证」，一条 e2e 保「协议全链路真跑通一次」；不做生产级全量回归、不配 CI。** 全部落到 `config/` 与 `tests/`，不硬编码。

### 1. 分层与深度
- **unit（默认跑）**：纯逻辑、DataPart/Task 契约 schema、接待编排分支、会话历史注入、09 一致性校验；无外部依赖、不打真模型。
- **integration（默认跑）**：检索质量 golden set（真检索栈，连 VM 已有数据）；A2A 进程内契约（见 §6）。
- **e2e（opt-in `@pytest.mark.e2e`）**：一条 happy-path，真 LLM + 真 Milvus/Redis 全链路走通一次。
- 默认 `pytest` 只跑无外部依赖的快测；打真模型/真 VM 的用 `@pytest.mark.llm` / `@pytest.mark.e2e` 隔离，显式 `-m e2e` 才触发。

### 2. LLM 依赖
- unit/integration 用 **fake LLM**：一个可控桩，按输入 prompt/意图返回预置的 `{is_service,intent,reason}` 或答复正文，专测编排与结构化输出 schema 校验（确定性 + 省钱）。
- 真实 LLM（通义千问 DashScope）只出现在 e2e happy-path 与 09 的提示词效果样例。

### 3. 检索质量（对齐 04，指标自算不加 RAGAS）
- **golden set 约 15–25 条**：`{question, expected_source_url, expected_points}`，放 `tests/fixtures/`。
- 跑纯检索（不涉 LLM）：指标 **recall@2 ≥ 0.8**（对齐 04 rerank 取 n=2）+ **source_url 出处命中准确**。
- 结果与「改动前后对照」写入 `docs/records`（与 09 记录体系共用目录）。
- RAGAS(`context_recall`/`context_precision`/`faithfulness`/`answer_relevancy`) **不作门禁**；作为 e2e 层**可选加分项**留给实现票（依赖重、judge 需打真 LLM，与 §2 冲突，故不进默认测）。

### 4. 核心业务分支（四条全部必测，用 fake 强制触发）
- ① 非客服 → 接待兜底 `COMPLETED`，**断言下游 0 次调用**；
- ② 下游(检索/答复)失败 → 接待兜底话术、任务仍 `COMPLETED`；
- ③ 检索空 → `COMPLETED` + `chunks:[]`（**空 ≠ 失败**）；
- ④ 正常链路 → 产出最终答复 `TextPart`。

### 5. 会话多轮（06 §9）
- 接待 executor 层用 **fake Redis / 内存 dict** 断言「第 2 轮把第 1 轮 `history` 正确注入下游 DataPart；单轮时 `history` 为空数组」。
- 真 Redis 的 key/TTL/轮数上限属实现细节，留给 e2e/手动（06 §9 已交实现票）。

### 6. A2A 交互测试层次
- **进程内驱动，不绑端口、不走网络**（`a2a-sdk` 1.2.2 无专用 test harness，但件齐）：
  - 纯内存单测：`DefaultRequestHandlerV2.on_message_send()` + `InMemoryTaskStore` + `SimpleRequestContextBuilder`/`EventConsumer`（或 `EventQueueLegacy`）直接驱动 `AgentExecutor`，断言产出的 `Task`/`Artifact`/`DataPart` 结构。
  - 更高保真（协议/序列化那一层）：`httpx.AsyncClient(transport=ASGITransport(app=build_app()))` + 匹配 Card URL，让 JSON-RPC+SSE 在进程内跑（复用 `src/hello_world/app.py:101` 的 `build_app()`）。
- 真 HTTP 绑定端口只在 §1 的 e2e 走一次。

### 7. e2e happy-path 环境
- 本地起 接待/检索/答复 三进程，**直连 VM `192.168.88.101` 已有 Milvus/Redis**（数据已灌）；不为测试另造 compose。

### 8. 09 一致性校验纳入 pytest
- 一个 unit 用例：比对 `docs/prompts` 记录的**提示词原文 + 生效参数（`top_k`/rerank 等）** vs `config/agents/*.yaml`/`config/common.yaml`；改了没同步记录 → 测试红。（无 CI 也生效，本地 `pytest` 触发。）

### 9. 框架、目录与依赖
- **pytest + pytest-asyncio**（venv 目前未装，实现票首个「测试脚手架」需补）。
- 目录：`tests/{unit,integration,e2e}/`、`tests/fixtures/`（golden set + fake LLM 桩 + ASGI app 装配）。
- markers：`llm` / `e2e`；默认不碰外部依赖。
- 对齐 uv/.venv（Python 3.10）。

### 10. CI / 门禁
- **不配 CI**（用户明确：不做 GitHub 展示）。作品集包装**收窄为只做 `README.md`**，测试与一致性校验仅本地 `pytest`。

### 依赖（后续实施票使用）
- 首个实施工单搭测试脚手架：`uv add --dev pytest pytest-asyncio`；建 `tests/` 目录与 `conftest.py`（fake LLM 桩 fixture、进程内 A2A 驱动 fixture、ASGITransport app fixture）。
- golden set 数据文件 `tests/fixtures/retrieval_golden.json`（待实施时按 RAGFlow 语料拟 15–25 条）。
- 复用 `src/hello_world/app.py` 的 `build_app()` 装配模式，三 Agent 各暴露可进程内驱动的入口。
- 与 09 共用 `docs/records/`（检索指标对照 + 提示词/参数变更历史）。
